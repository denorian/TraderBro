# AoDivergenceReversalStrategy — алгоритм работы

Стратегия разворота на **подтверждённой** AO-дивергенции «Twin Peaks» + ангуляции (угол отхода
от линии Jaw Alligator) по системе Билла Вильямса.

Класс: `core/strategies/AoDivergenceReversalStrategy.java`
Зависимые детекторы: `core/indicators/AoTwinPeaksDetector.java`, `core/indicators/AngulationDetector.java`.

Все решения **look-ahead-free**: используются только бары `≤ endIndex`. По умолчанию стратегия
выключена (`strategies.ao-divergence.enabled=false`) до валидации walk-forward бэктестом.

## 1. Правило входа — `confirmedReversal(series, params, endIndex)`

Оценивается на закрытом баре `endIndex`. Возвращает `LONG`/`SHORT` либо `null` (нет входа).

1. Берём под-серию баров `0..endIndex` (`series.getSubSeries(0, endIndex+1)`).
2. На под-серии считаем:
   - **AO** = SMA(5) − SMA(34) медиан цен;
   - **Alligator** (Jaw/Teeth/Lips, сдвиги и ATR 14);
   - **ATR(14)**.
3. `AoTwinPeaksDetector.scan(sub, ao, ...)` → список дивергенций (см. п. 2).
4. Идём по событиям **от самого нового к старому** и берём **первое** со статусом `CONFIRMED`:
   - направление: `BEARISH → SHORT`, `BULLISH → LONG`;
   - если `SHORT` и `allowShort == false` → вход невалиден (`null`);
   - **ангуляция** (`angulated`): на пике 2-й дивергенции угол отхода цены от Jaw
     `angleAtr >= thresholdAtrPerBar (0.1)`;
   - **закрытие за «Зубы»** (`closePast`), на текущем баре `endIndex`:
     - для `BEARISH`: `close < teeth`;
     - для `BULLISH`: `close > teeth`;
   - если все условия сошлись → возвращаем направление (вход состоялся);
   - если первая `CONFIRMED` дивергенция не прошла угол/«Зубы» → сразу `null`
     (**к более старым дивергенциям не переходит**).
5. Нет подходящей `CONFIRMED` дивергенции → `null`.

> Важно: правило входа рассматривает только **самую новую** подтверждённую дивергенцию.
> Неудача угол/«Зубы» на ней не приводит к перебору более старых.

## 2. Детектор Twin Peaks — `AoTwinPeaksDetector`

Сканирует две полярности отдельно: **пики выше нуля** (медвежьи) и **впадины ниже нуля**
(бычьи). Для каждой:

1. Идём по барам; пока AO в нужном знаке (`>0` для пиков, `<0` для впадин) — копим
   экстремумы. Пересечение нуля обрывает текущую серию.
2. Экстремум в точке `cand = i - aoPeakWindow` подтверждается, когда `aoPeakWindow=2` баров
   справа строго ниже (для пика) / выше (для впадины).
3. Условия дивергенции между двумя соседними экстремумами:
   - расстояние: `minPeakDistance (5) ≤ dist ≤ maxPeakDistance (60)`;
   - **истощение**: 2-й экстремум слабее по модулю (пики: `val2 < val1`; впадины: `val2 > val1`);
   - **подтверждение ценой**: на 2-м экстремуме новый максимум (медвежья) / новый минимум
     (бычья) относительно 1-го;
   - **амплитуда 1-го пика** `≥ minPeakAbsAtr (0.2) × ATR` (отсечка шума).
4. **Статус** (`status`):
   - окно подтверждения = `extreme + confirmBars (10)`;
   - окно ещё не прошло → `UNCONFIRMED`;
   - окно прошло и в нём AO развернулся (2 подряд падающих бара для верха / растущих для
     низа) → `CONFIRMED`;
   - иначе → `EXPIRED`.

> Ключевой нюанс: для уже подтверждённой дивергенции `status()` **остаётся `CONFIRMED`
> навсегда** в последующих сканах (проверка по фиксированным барам `extreme+1..extreme+10`,
> не зависит от текущего `now`). Поэтому одна дивергенция «перестреливается» на каждом
> следующем баре, пока остаётся самой новой подтверждённой.

## 3. Ангуляция — `AngulationDetector.detect`

1. Находим индекс пика 2-й дивергенции (`aoPeak2Ts`).
2. Ищем якорь — последний бар, где цена касалась линии Jaw, в пределах `lookbackBars (60)`.
3. Считаем наклоны цены и Jaw на окне от якоря до пика, нормализуем разницу на ATR на бар
   → `angleAtr`.
4. Стратегия требует `angleAtr ≥ thresholdAtrPerBar (0.1)`.

Ангуляция — **усилитель/фильтр валидности** разворота, а не самостоятельный вход: по Вильямсу
разворот без ангуляции невалиден.

---

## 4. Правило выхода — `reversed`

На текущем баре — срабатывание **блюдца AO** в противоположную сторону:
- для длинной позиции — `ao.isBearishSaucer(idx)`;
- для короткой — `ao.isBullishSaucer(idx)`.

Стоп: за экстремумом на 2-м пике дивергенции, на `stopBufferAtr (0.3) × ATR`.

---

## 5. Как работает в бэктесте (`BacktestRunner`)

1. `strategy.build(series, params)` → ta4j `Strategy`, правило входа = «`confirmedReversal` не
   пустой».
2. На каждом баре `i` (с `i=1`) вычисляется `shouldEnter(i-1)` — сигнал на **закрытии** бара
   `i-1`, исполнение на **открытии** бара `i` со спредом и комиссией (защита от look-ahead).
3. Пока позиция открыта — входы не генерируются, поэтому в БД сигналов заметно меньше, чем
   «наивных» срабатываний правила на каждом баре.

## 6. Практическая заметка: селективность и «перестреливание»

Проверено на реальных данных BTCUSDT ONE_HOUR (2025-09 … 2026-10): за год только **5
подтверждённых дивергенций** (2026-01-10, 2026-02-01, 2026-07-15, 2026-07-22, 2026-09-11).

- Из-за «перестреливания» одна подтверждённая дивергенция даёт сотни сигналов подряд
  (например, ~327 сигналов в феврале при 1 дивергенции). Это by design, но стоит учитывать
  при анализе количества сигналов.
- После 2026-07-22 новых подтверждённых дивергенций, прошедших угол/«Зубы», не было — поэтому
  пины на графике обрываются, хотя бары непрерывны до конца октября. Это **селективность
  стратегии, а не сбой данных**.
- `AlligatorAoStrategy` (другая логика — запутанность Alligator + блюдце AO) заметно менее
  селективна и продолжает давать пины, когда `AoDivergenceReversalStrategy` молчит.
