## 2. АНАЛИТИЧЕСКАЯ БАЗА: КАКИЕ СТРАТЕГИИ РАБОТАЮТ В КРИПТЕ (выводы исследований)

| Класс стратегии | Доказательность | Профиль | Решение для TraderBro |
|---|---|---|---|
| **Тренд-фолловинг (ансамбль Donchian/MA, короткие lookback 5–30 дн)** | Высокая: Combo-ансамбль на BTC — CAGR ~30%, Sharpe 1.58, MaxDD 19% vs 80%+ у HODL; ротационный портфель топ-20 ликвидных альтов — Sharpe 1.57 нетто комиссий, alpha 10.8% к BTC, MaxDD 11% (Concretum/Quantified Strategies, 2026) | Win-rate <40%, profit factor >1.5; зарабатывает немногими большими движениями | **Ядро портфеля**: Donchian-ансамбль + ротация топ-N |
| **Пробой максимумов (MAX: покупка N-дневного хая, N=10–50)** | Высокая: подтверждено out-of-sample на BTC за последние 2,5 года; MIN-покупка (ловля падений) деградировала — не использовать (Quantpedia, 2024–2026) | Простое, устойчивое к параметрам правило | Отдельная стратегия `MaxBreakoutStrategy` (лонг-онли) |
| **Моментум-ротация (топ-N по доходности за K дней, ежемесячная ребалансировка)** | Средняя-высокая: до 56.9% p.a., Sharpe 1.68 на портфеле (исследование, 18 мес.); ротационный портфель топ-20 — Sharpe 1.57 (см. выше) | Портфельная, не одиночная | Новая `MomentumRotationStrategy` (портфельная) |
| **Возврат к среднему (Bollinger/RSI)** | Средняя: win-rate 60–70%, но катастрофа в сильных трендах (Coinquant, 2026); на MOEX-данных без фильтра — убыточна (наш анализ этапа 1) | Высокая частота сделок, маленький профит-фактор | Только **с режимным фильтром** (AlligatorState=RANGE + ADX < порога) |
| **ATR-волатильные пробои (Sudden Death-подобные: вход по k×ATR, стоп/тейк в ATR)** | Средняя: 17 лет на форексе, win-rate ~39%, TP:SL = 2:1–4:1, матричный форвард-тест (Empirix) | Робастна к волатильным рынкам | Новая `AtrVolatilityBreakoutStrategy` |
| **Сигналы Вильямса (Alligator+AO, дивергенция+ангуляция)** | Наш этап 3.4; режимный фильтр Аллигатора особенно ценен в крипте (долгие боковики → резкие тренды) | Среднечастотные тренд/развороты | Уже есть; включить крипту в конфиг |
| **Funding-rate арбитраж (спот + перп, дельта-нейтраль)** | Высокая, но офф-скоуп: 5.98–11.4% APR фикс. (Boros/Binance-Hyperliquid, 2025–2026); требует перпетуалов и маржи на нескольких площадках | Низкий риск, ~0 направленной экспозиции | **Не реализуем в 3.7** — `TODO(этап 4): funding-rate arb` (нужен Binance Futures API) |
| **Кросс-биржевой/HFT арбитраж** | Недоступна розничному API (latency) | — | Не реализуем |

**Общие правила для крипто-портфеля** (из исследований): комиссии критичны для высокооборотных стратегий — чувствительность тестировать на 10/25/50 б.п.; ребалансировка волатильного сайзинга — только при отклонении аллокации >20% (снижает издержки); размер-эффект отсутствует в топ-100 по ликвидности — стратегии работают по всему топ-25; диверсификация по 15–25 активам снижает MaxDD вдвое.

## 3. ЗАДАЧА 1: ЮНИВЕРС ТОП-25 КРИПТОВАЛЮТ

1. **`CryptoUniverseService`** (`com.traderbro.data.binance`): ежедневно (после обновления CoinGecko) формирует торгуемый юниверс: топ-`crypto.universe.size` (по умолчанию 25) по `market_cap_rank`, исключая стейблкоины (список-фильтр `crypto.universe.stablecoin-exclude`: USDT, USDC, DAI, FDUSD, USDE, TUSD — конфиг) и активы без спотовой пары к USDT на Binance со статусом TRADING.
2. Автоподключение/отключение пар: новый вошёл в топ-25 → загрузка истории (`CryptoHistoryLoader`, идемпотентно) + подписка стрима + запись в `audit_events`; выбыл → стрим останавливается, история сохраняется, стратегии по инструменту → пауза (новых сигналов нет), событие в аудит + Telegram `INFO`.
3. Минимальный фильтр ликвидности: среднедневной объём торгов (quoteVolume за 20 дней, из Binance `ticker/24hr` агрегированно) ≥ `crypto.universe.min-quote-volume-usd` (по умолчанию $20 млн) — отсекает «мёртвые» хвосты топ-25.
4. Конфиг: `crypto.pairs` заменить на режим `auto` (юниверс из сервиса) / `manual` (явный список, как в 3.6). По умолчанию `auto`, size=25.
5. Liquibase: колонка `instruments.universe_member BOOLEAN`, `universe_updated_at` — для быстрых выборок.

## 4. ЗАДАЧА 2: НОВЫЕ СТРАТЕГИИ

### 4.1. `MaxBreakoutStrategy` (лонг-онли, крипта)

- Вход: close > максимум high за N дней (N из конфига, ансамбль: 10/20/50 — три субстратегии, голосование большинством или отдельные позиции-транши по 1/3 риск-капитала — реализуй транши);
- Выход: close < минимум low за M дней (M = N/2, по умолчанию) **или** трейлинг-стоп `atrMult × ATR(14)`;
- Лонг-онли (спот); фильтр: торговать только если BTC выше своей SMA(200) — «рыночный фильтр» (параметр `marketFilter: BTC_SMA200`, выключаемый);
- Параметры в `strategy_config`, бэктест обязателен.

### 4.2. `MomentumRotationStrategy` (портфельная)

- **Портфельная стратегия** — работает не per-instrument, а на юниверсе: раз в `rebalance-days` (по умолчанию 30 календарных дней, на закрытии дневной свечи) ранжирует инструменты юниверса по доходности за `lookback-days` (по умолчанию 30; из исследований — короткие lookback 5–30 дней лучшие);
- Держит топ-`hold-count` (по умолчанию 5) равновзвешенно **с волатильным сайзингом**: вес ∝ 1/vol(20д), нормировано; буфер ротации: инструмент выбывает из портфеля, только если выпал из топ-(`hold-count`+2) — снижает оборот (аналог 20%-порога из исследований);
- Рыночный фильтр: если BTC < SMA(200) — портфель в кэше (USDT), позиций нет;
- Архитектурно: новый интерфейс `PortfolioStrategy extends TradingStrategy` с методом `TargetPortfolio evaluate(UniverseSnapshot)`; оркестратор сигналов превращает целевой портфель в набор ребалансирующих сигналов (дельта к текущему); в бэктесте — отдельный `PortfolioBacktestRunner` (см. задачу 3);
- Без исполнения по крипте (этап 3.6 — только данные) стратегия работает в режиме сигналов/бэктеста; пометь `TODO(этап 4): исполнение`.

### 4.3. `AtrVolatilityBreakoutStrategy`

- Вход: цена > high[1] + `kOrder × ATR(20)` (по умолчанию kOrder=1) на дневном/1ч таймфрейме; шорт зеркально (только если будет исполнение — пока сигналы);
- Стоп: `kSL × ATR` (по умолчанию 2), тейк: `kTP × ATR` (по умолчанию 3, диапазон тестирования 2–4), трейлинг `kTSL × ATR` после достижения 1×ATR прибыли;
- Один вход на инструмент в `cooldown-bars` (по умолчанию 5).

### 4.4. Режимный фильтр для `BollingerMeanReversionStrategy` (доработка)

- Для крипты разрешать входы только если `AlligatorState = SLEEPING/RANGE` **и** ADX(14) < `adx-threshold` (по умолчанию 20); иначе verdict `FILTERED`, причина `TRENDING_MARKET`. ADX — из каталога ta4j (`ADXIndicator`), если отсутствует — реализуй и пометь `// TODO: verify API`.

## 5. ЗАДАЧА 3: ПОРТФЕЛЬНЫЙ БЭКТЕСТ

1. **`PortfolioBacktestRunner`**: прогон стратегии (или набора) на **множестве инструментов как едином портфеле**: единый капитал, волатильный сайзинг позиций (риск на сделку % от equity портфеля), корреляционный лимит (суммарная экспозиция на кластер высококоррелированных активов ≤ лимита; кластеры — по скользящей 60-дневной корреляции > 0.8, порог в конфиге), единая equity-кривая портфеля + вклад каждого инструмента.
2. Метрики портфеля: CAGR, Sharpe/Sortino, MaxDD, Calmar, alpha/beta к BTC (бенчмарк BTCUSDT), turnover (оборот в % капитала/мес — контроль издержек), метрики нетто комиссий при 10/25/50 б.п. (чувствительность — обязательный блок отчёта).
3. Walk-forward по портфелю: те же окна train/test.
4. Хранение: `backtest_runs` + `backtest_portfolio_equity` (`run_id, ts, equity, benchmark_equity`) + агрегаты по инструментам в существующих таблицах.
5. REST: `POST /api/backtests/portfolio` (тело: strategyIds, universe: `TOP25` | явный список, период, издержки, начальный капитал), `GET /api/backtests/{id}/portfolio` (метрики, equity, вклад инструментов, чувствительность к комиссиям). Обнови `openapi.yaml`.
6. **Сравнительный отчёт «стратегия × режим»**: после прогона всех крипто-стратегий на юниверсе топ-25 — автоматический Markdown-отчёт в `reports/crypto-strategy-matrix/`: таблица метрик по каждой стратегии, разбивка по режимам рынка (BTC выше/ниже SMA200; высокая/низкая волатильность по ATR-процентилю), рейтинг по Шарпу нетто 25 б.п. Отчёт — файл + Telegram `BACKTEST_COMPLETED` со ссылкой.
